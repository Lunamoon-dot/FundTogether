# HED-MVP-1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace new-campaign Workflow B advances with the HED-MVP-1 vendor-payment escrow journey while preserving existing A/B obligations and shared organization/auth/storage data.

**Architecture:** Add a separate HED contract and deployment identity; financial truth remains contract state and events. Additive PostgreSQL projections and NestJS APIs own request metadata, criterion records and private files; React consumes generated API/ABI boundaries and never treats an HTTP response or transaction hash as payout success.

**Tech Stack:** Solidity 0.8.24/Foundry, OpenZeppelin, NestJS/TypeScript, Drizzle/PostgreSQL, Viem, React/TypeScript.

**Spec:** `docs/hed-mvp-design.md`, `GOAL.md`

## Global Constraints

- Use only local exact-transfer MockUSDC with 6 decimals; no fiat, P2/P3, partial funding, parallel requests, multi-installments, bond, voting or AI review.
- Keep A/B contracts, migrations, deployments, account/wallet bindings and evidence files readable; no reset, DROP, conversion or mutation of their obligations.
- HED funding is complete before vendor commitment; reserve the whole `Q`; only verified vendor wallet receives D/P.
- Contract events drive indexer projections keyed by chain, deployment, contract, campaign and request; projections/API never authorize a payout.
- All financial amounts are `uint256`/`bigint`; no JS floating-point values.
- Private originals remain ACL-protected; public redacted bundles contain no PII, presigned URLs or secrets.
- Never report wallet submission, receipt, or upload as indexed completion.

## Review Focus

- A return or reclassification after final authorization must invalidate the authorization before execution.
- A zero-deposit request must still occupy the one-request slot and not permit a second reserve.
- An open case or stale evidence version must not lead to final payment or outcome verification.
- A token transfer failure/non-exact transfer must roll back all custody, reserve and paid counters.
- A replayed, orphaned, or wrong-deployment event must not update an HED projection.
